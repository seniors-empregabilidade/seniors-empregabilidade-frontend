# Seniors – Empregabilidade Frontend

Web frontend for the Seniors – Empregabilidade project, developed by the AGES team. The product interface is written in Brazilian Portuguese; source code and technical documentation are written in English.

This repository currently contains a technical foundation only. Domain entities, business features, authentication, and a visual design system will be introduced after their requirements are confirmed.

## Technology

- React 19 and TypeScript 6
- Vite 8, client-rendered as a single-page application (SPA)
- TanStack Router with file-based routes
- TanStack Query with its standard in-memory client
- shadcn/ui, Tailwind CSS 4, and Base UI
- Axios, React Hook Form, and Zod
- Vitest, React Testing Library, and Cypress
- ESLint, Prettier, Husky, lint-staged, and commitlint

## Requirements

- Node.js 24 LTS
- pnpm 11.16.0 through Corepack
- Google Chrome or Chromium for end-to-end tests
- The backend running at the URL configured by `VITE_API_URL`

## Local setup

```bash
corepack enable
pnpm install --frozen-lockfile
cp .env.example .env.local
pnpm dev
```

The application is available at `http://localhost:5173`. The default API URL is `http://localhost:8000/api/v1`; `.env.local` may override it without being committed.

On PowerShell, copy the environment file with:

```powershell
Copy-Item .env.example .env.local
```

## Commands

| Command              | Purpose                                      |
| -------------------- | -------------------------------------------- |
| `pnpm dev`           | Start the Vite development server            |
| `pnpm build`         | Generate routes, build, and type-check       |
| `pnpm typecheck`     | Run the TypeScript compiler without emitting |
| `pnpm lint`          | Run ESLint with zero warnings allowed        |
| `pnpm format:check`  | Check formatting with Prettier               |
| `pnpm test`          | Run unit and component tests once            |
| `pnpm test:coverage` | Run tests with the 80% coverage gate         |
| `pnpm e2e:open`      | Open Cypress for local development           |
| `pnpm e2e:ci`        | Serve the build and run Cypress in Chrome    |
| `pnpm validate`      | Run all checks except Cypress                |
| `pnpm validate:push` | Run every local quality gate                 |

Git hooks run staged formatting/linting and a full type check before commits, validate Conventional Commits in `commit-msg`, and run the complete validation including Cypress before pushes. Do not bypass them.

## Technical structure

The repository intentionally avoids speculative domain folders. Its current structure contains only the technical foundation:

```text
.
├── .github/              # CI, Dependabot, CODEOWNERS, and PR guidance
├── .husky/               # Local pre-commit, commit-msg, and pre-push hooks
├── config/               # ESLint, Prettier, commitlint, and lint-staged
├── cypress/              # Browser smoke and accessibility tests
├── docs/                 # Architecture, ADRs, and engineering policies
├── src/
│   ├── components/ui/    # Source-owned shadcn/ui components
│   ├── config/           # Validated public runtime configuration
│   ├── lib/              # HTTP, errors, Query client, and utilities
│   ├── routes/           # TanStack Router route declarations
│   ├── test/             # Shared test setup and cross-cutting tests
│   ├── main.tsx          # Browser application entry point
│   ├── router.tsx        # Router instance and type registration
│   └── styles.css        # Tailwind entry point and neutral UI variables
├── components.json       # shadcn/ui CLI configuration
├── cypress.config.ts     # Cypress config; its location defines the project root
├── vite.config.ts        # Vite, routing, Tailwind, and Vitest configuration
└── tsconfig*.json        # TypeScript project boundaries
```

The root keeps only files that are conventional entry points or must be discovered by their tools. General-purpose tooling configuration belongs in `config/`.

`src/routeTree.gen.ts` is generated by the TanStack Router Vite plugin and must never be edited manually. New business-oriented folders should follow confirmed scope, not hypothetical entities.

When product scope is confirmed, organize new code around real features or domain capabilities. Do not create placeholder `features`, `hooks`, `schemas`, `services`, `store`, or entity folders merely to demonstrate a future architecture. Record a structural decision in an ADR only when it affects multiple features or establishes a lasting boundary.

## Environment

Only variables prefixed with `VITE_` are exposed to browser code. Never place secrets in frontend variables.

| Variable       | Required | Default                        | Purpose      |
| -------------- | -------- | ------------------------------ | ------------ |
| `VITE_API_URL` | No       | `http://localhost:8000/api/v1` | API base URL |

Production hosts must provide SPA fallback routing to `index.html`.

## Accessibility

WCAG 2.2 AA is the project target. Use semantic HTML, complete keyboard interactions, visible focus, sufficient contrast, accessible names, and reduced-motion support. Cypress runs axe checks, but automated checks do not replace manual keyboard and screen-reader review.
